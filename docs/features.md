## Food `/food`

- Meal logs + macros, AI meal-photo scanner, quick-add search (matches menu item OR restaurant name via widened `/menu-items/search`, results grouped by restaurant, meal-type picker).
- **Chain-restaurant search** (Spoonacular direct API, `artifacts/api-server/src/lib/spoonacular.ts`): explicit-submit "Search chains" surfaces REAL published nutrition for national/regional chains (web + mobile) with one-tap log via the shared log hook. Two-call shape (GET `/chain-menu-items/search` returns id/name/restaurant/image, no macros → GET `/chain-menu-items/:id` returns clamped macros; search registered before `:id`). Untrusted upstream Zod-validated/clamped/sanitized, https-only images; layered quota defense = one combined per-user hourly limiter on BOTH routes + module global daily budget (ET reset, counts real calls only) + 1h caches; coarse 503 (no_key/budget/timeout/upstream) + 404 not-found; key from `SPOONACULAR_API_KEY`, never logged. Premium-gated, not requirePatient (staff self-track).
- **Barcode scanner** (2026-07): GET `/barcode-products/:barcode` (6-14 digits) → Open Food Facts (`artifacts/api-server/src/lib/openfoodfacts.ts`: Zod-validated/clamped untrusted upstream, 24h cache, 8s timeout, UPC-12 leading-zero retry, kJ→kcal + salt→sodium fallbacks, implausible sodium >8g → null, no-energy → 404; 60/hr per-user limiter, coarse 404/503, https-only images, User-Agent per OFF policy). Web: `barcode-scanner-dialog.tsx` (@zxing/browser camera + always-available manual number entry) from Food Quick Add card; Mobile: `components/track/BarcodeScanCard.tsx` (expo-camera CameraView native-only, manual entry on Expo web). Per-serving vs per-100g basis labeled in both UIs; logs via shared log-menu-item hooks (which pass through optional `servingSize`).

## Restaurants (Dining Out Guide)

- 18 curated local chains, each with a full baked-in menu (~26-29 items; generated by `scripts/src/gen-menus.ts` → `lib/db/src/restaurant-menu-extra.ts` as `RESTAURANT_MENU_EXTRA`, merged in `seedRestaurants` curated-first with case-insensitive within-seed dedupe + exact-name DB idempotency, so prod picks them up on startup), healthy-pick tips (staff-editable), "Log to food diary" buttons on menu items (web + mobile via shared `use-log-menu-item` hook).
- Patient-added restaurants: `restaurants.owner_user_id` NULL = curated; owned rows are patient-private — every restaurant/menu route filters `(ownerUserId IS NULL OR = me)`, admin restaurant/menu CRUD requires `ownerUserId IS NULL`, never expose ownerUserId, Restaurant schema has required `isMine`.
- POST /restaurants/custom (requirePatient, 5/day in-memory limit, 30/user cap, partial unique index on (owner, lower(name)), optional `location` input) generates a web-grounded menu: single openai.responses.create call (gpt-5.4 + web_search tool, web pages marked data-not-instructions) pulls REAL dish names, falls back to non-grounded chat.completions "typical menu" on any failure; nutrition always AI-estimated; `restaurants.menu_source` stores bare source domain (cleanDomain regex, stripLinks on all AI text) shown as "Dish names from <domain>" on web+mobile; Zod-validated, clamped, "looksLikeRestaurant" gate, AI-estimate disclaimers in UI.
- Patients edit their OWN restaurant menus (web UI only): POST /restaurants/:id/menu-items, PATCH+DELETE /menu-items/:id — requirePatient, ownership-bound, uniform 404s, 40-item cap FOR UPDATE in transaction. DELETE /restaurants/:id owner-only.
- "Order on DoorDash" deep-links (`doordash.com/search/store/<name>` — no public ordering API, hand-off only) on web + mobile.

## Activity & Sleep `/activity` (2026-07)

- Manual activity/sleep logging (10 pts each, manual-only, dedupe `activity_log:<date>`/`sleep_log:<date>`), 7/30-day charts (`days` query param is NUMERIC enum 7|30), streak.
- Device pairing in `device_connections`: **Oura ring** via personal access token (plaintext in DB by design, only `tokenLast4` ever returned/logged; connect validates token live, sync pulls daily_activity + long_sleep sessions + daily_sleep score, upserts `onConflictDoUpdate` on partial unique (userId, source, externalId) so re-syncs refresh values; per-connection toggles syncActivity/syncSleep; disconnect optionally removes synced rows via `?removeData`; rate limits connect 5/hr, sync 4/hr, in-memory).
- **Phone steps** (mobile iOS only): expo-sensors Pedometer 7-day read → preview → import as source 'phone' (externalId `phone:<date>`); Android/web get honest "not available" copy. **Apple Health**: info-only card — needs App Store build, no fake toggle.
- Nightly Oura sync cron 6:00 ET (`activityScheduler.ts`, sequential, per-user try/catch). Synced rows are NOT deletable via API (DELETE manual-only → 404).
- Routes patient-only + premium-gated; morning briefing includes yesterday's active minutes/steps + last night's sleep. Mobile: Track tab 5th segment "Move" (`components/track/MoveTab.tsx`).
